## Phase 3 — In-Memory Storage Layer

**File**: `src/storage.go`

**Goal**: Build a thread-safe, in-memory store for expenses.

**Functions to implement**:

| Function | Behavior |
|---|---|
| `NewExpenseStore()` | Returns a new empty store with `nextID = 1`. |
| `Create(exp Expense) Expense` | Assigns an ID and stores the expense. Returns the stored expense. |
| `GetAll() []Expense` | Returns all expenses as a slice. Returns an empty slice, not nil. |
| `GetByID(id int) (Expense, bool)` | Returns the expense and `true`, or zero value and `false`. |
| `Delete(id int) bool` | Removes the expense. Returns `true` if it existed, `false` if not. |
| `Filter(category, search string) []Expense` | Filters by exact category match and case-insensitive title substring. |
| `GetTotal() float64` | Returns the sum of all `Amount` fields. |
| `GetTotalByCategory(cat string) float64` | Returns the sum of `Amount` for the given category. |
| `GetMonthlySummaries() []MonthlySummary` | Groups expenses by `YYYY-MM` month. |

**Rules**:
- `ExpenseStore` holds a `sync.RWMutex`. Call `RLock/RUnlock` in read methods. Call `Lock/Unlock` in write methods.
- `GetAll()` and `Filter()` return `[]Expense{}` (empty slice). They never return `nil`.
- IDs are auto-incremented integers that start at `1`.
- `Filter()` with both arguments as empty strings returns all expenses.
- The `contains` helper implements case-insensitive substring search: `strings.Contains(strings.ToLower(s), strings.ToLower(substr))`.

**Test Cases**:
- Create one expense. `GetAll()` must return 1 item.
- Create two expenses. `GetByID(1)` must return the first.
- Create and delete one expense. `GetByID(id)` must return `false`.
- Create food and transport expenses. `Filter("food", "")` must return 1 item.
- Create two expenses with amounts 25 and 75. `GetTotal()` must return `100.0`.
- `GetTotalByCategory("food")` with one food expense of 30 must return `30.0`.
- `GetAll()` on empty store must return an empty slice, not nil.
- `Delete()` on a non-existent ID must return `false`.
- `Filter("", "pizza")` with one expense titled "Pizza" must return 1 item.
- `Filter("", "PIZZA")` must return the same result as `Filter("", "pizza")` (case-insensitive).
- `Filter("", "xyz")` with no matching title must return an empty slice.
- `GetMonthlySummaries()` with one food expense in August 2026 must return a summary where `ByCategory["food"]` equals the expense amount. The map must be `map[string]float64`, not `map[string]interface{}`.

**Verification (manual)**:
- Run `go vet ./...`. It must exit with code 0.

**Status**: `[ ]` Not started

## Phase 4 — HTTP Handlers

**File**: `src/handlers.go`

**Goal**: Implement all REST API endpoints using Echo.

**Endpoints**:

| Method | Path | Handler | Description |
|---|---|---|---|
| `POST` | `/api/v1/expenses` | `CreateExpense` | Add a new expense |
| `GET` | `/api/v1/expenses` | `GetExpenses` | List all, or filter by `?category=` or `?search=` |
| `GET` | `/api/v1/expenses/:id` | `GetExpenseByID` | Get one expense |
| `DELETE` | `/api/v1/expenses/:id` | `DeleteExpense` | Remove an expense |
| `GET` | `/api/v1/expenses/totals` | `GetTotals` | Total amount overall and by category |
| `GET` | `/api/v1/summary/monthly` | `GetMonthlySummary` | Monthly breakdown |

**Rules**:
- Return `201 Created` on `POST`.
- Return `204 No Content` on successful `DELETE`.
- Return `404 Not Found` if the expense does not exist.
- Return `400 Bad Request` for invalid input.
- List endpoints return a JSON array. An empty result is `[]`, never `null`. Initialise the slice with `make([]Expense, 0)` before returning.
- All handlers must have Swagger annotations.
- Handlers are methods on `Handler` struct (dependency injection). They do not reference a global variable.

**Test Cases** (HTTP-level):
- `POST /api/v1/expenses` with valid JSON must return `201` and a body with an `id` field.
- `POST /api/v1/expenses` with missing `title` must return `400`.
- `GET /api/v1/expenses` with one stored expense must return a JSON array of length 1.
- `GET /api/v1/expenses?category=food` must return only food expenses.
- `GET /api/v1/expenses/:id` with a valid ID must return `200`.
- `GET /api/v1/expenses/:id` with a non-existent ID must return `404`.
- `DELETE /api/v1/expenses/:id` with a valid ID must return `204`.
- `DELETE /api/v1/expenses/:id` with a non-existent ID must return `404`.
- `GET /api/v1/expenses/totals` must return a `total` field.
- `GET /api/v1/summary/monthly` must return an array.

**Verification (manual)**:
- Start the server. Run `curl -s http://localhost:8080/api/v1/expenses`. It must return `[]`.
- Run `curl -s -X POST -H "Content-Type: application/json" -d '{"title":"Lunch","amount":12.5,"category":"food","date":"2026-08-01T00:00:00Z"}' http://localhost:8080/api/v1/expenses`. It must return an expense with `id: 1`.

## Phase 6 — Swagger Generation

**Goal**: Generate Swagger docs from code annotations into the `api-docs/` directory.

**Why `api-docs/`?** Industry convention separates machine-generated OpenAPI artifacts from hand-written project docs. Tools like Redoc, Stoplight, and GitHub Actions expect OpenAPI files in a named directory at the repo root.

**Tasks**:
1. Run `swag init --output ./api-docs --packageName docs` from the project root.
2. Confirm `api-docs/` contains `docs.go`, `swagger.json`, and `swagger.yaml`.
3. Use `_ "github.com/Amazing-Stardom/ExpenseSync/api-docs"` as the blank import in `main.go`.

**Note on the import**: The directory name has a hyphen, but Go allows hyphenated paths in import statements. The blank import only triggers the `init()` side effect, so no identifier collision occurs.

**Verification (manual)**:
- Open `http://localhost:8080/swagger/index.html`.
- Confirm all six endpoints appear.
- Use "Try it out" on `POST /api/v1/expenses`. It must return `201`.

## Phase 7b — Makefile

**File**: `Makefile`

**Goal**: Provide a single entry point for all local development and test commands.

The README and the automated reviewer will use `make` targets. This removes ambiguity about exact flags and paths.

**Targets to implement**:

| Target | Command it runs | Purpose |
|---|---|---|
| `make run` | `go run main.go` | Start the server locally |
| `make test` | `go test ./... -v` | Run all tests |
| `make cover` | `go test ./... -cover` | Run tests with coverage |
| `make swagger` | `swag init --output ./api-docs --packageName docs` | Regenerate OpenAPI docs |
| `make build` | `go build -o expensesync .` | Compile binary |
| `make docker-build` | `docker build -t ExpenseSync:latest .` | Build Docker image |
| `make docker-run` | `docker run -p 8080:8080 ExpenseSync:latest` | Run in Docker |
| `make docker-up` | `docker-compose up --build` | Start with Compose |
| `make docker-down` | `docker-compose down` | Stop Compose |

**Makefile content**:
```makefile
.PHONY: run test cover swagger build docker-build docker-run docker-up docker-down

run:
	go run main.go

test:
	go test ./... -v

cover:
	go test ./... -cover

swagger:
	swag init --output ./api-docs --packageName docs

build:
	go build -o expensesync .

docker-build:
	docker build -t ExpenseSync:latest .

docker-run:
	docker run -p 8080:8080 ExpenseSync:latest

docker-up:
	docker-compose up --build

docker-down:
	docker-compose down
```

**Test Cases**:
- `make run` must start the server without errors.
- `make test` must exit with code 0 with all tests passing.
- `make docker-build` must produce a valid image.
- `make docker-run` must serve `GET /health` correctly.

**Verification (manual)**:
- Run `make test`. All tests must pass.
- Run `make docker-up` and `curl http://localhost:8080/health`. It must return `{"status":"ok"}`.
